# Academic origins of the ranking and graph-seeding methods

This inventory follows the ranking and seeding options exposed by the search/evaluation pipeline in `src/services/search_pipeline.py` and `src/services/batch_evaluation.py`. “Origin” refers to the underlying published algorithm; names that are project-specific combinations or heuristics are identified as such rather than attributed to a paper that did not introduce them.

## Ranking methods

| Implemented option | Method used in this project | Academic source / qualification |
|---|---|---|
| `lexical` | PostgreSQL full-text search with a lexeme-quorum candidate filter and `ts_rank` ordering. The SQL aliases this score `bm25`, but it is **not standard BM25**. | [Robertson & Zaragoza, “The Probabilistic Relevance Framework: BM25 and Beyond” (2009)](https://doi.org/10.1561/1500000019) is the BM25 reference, not the origin of PostgreSQL `ts_rank`; it is included as the closest named lexical-ranking method. |
| `vector` | Dense query/chunk embeddings, ordered by cosine distance; the app uses `qwen3-embedding:0.6b` (768 dimensions). | The vector-space retrieval lineage is [Salton, Wong & Yang, “A Vector Space Model for Automatic Indexing” (1975)](https://doi.org/10.1145/361219.361220). For the actual embedding model, see [Zhang et al., “Qwen3 Embedding: Advancing Text Embedding and Reranking Through Foundation Models” (2025)](https://doi.org/10.48550/arXiv.2506.05176). Neither paper introduces cosine similarity itself. |
| `hybrid_max` | Returns the existing hybrid retrieval order, which combines lexical and vector ranks using RRF. Despite the option name, this implementation does not take a maximum of component scores. | [Cormack, Clarke & Büttcher, “Reciprocal Rank Fusion Outperforms Condorcet and Individual Rank Learning Methods” (2009)](https://doi.org/10.1145/1571941.1572114). |
| `rrf` | Reciprocal-rank fusion of the lexical and vector result lists. | [Cormack, Clarke & Büttcher (2009)](https://doi.org/10.1145/1571941.1572114). |
| `cross_encoder` | Neural reranking: a query and candidate chunk are jointly scored by a cross-encoder. The default configured model is `cross-encoder/mmarco-mMiniLMv2-L12-H384-v1`. | [Nogueira & Cho, “Passage Re-ranking with BERT” (2019)](https://doi.org/10.48550/arXiv.1901.04085) is an early seminal neural passage-reranking paper. It is a methodological antecedent, not the paper for the configured MiniLM checkpoint. |
| `ppr` | Personalized PageRank over the article/entity graph, personalized from the selected seed method; article scores are degree-normalized. | [Haveliwala, “Topic-Sensitive PageRank” (2002)](https://doi.org/10.1145/511446.511513) develops topic-biased PageRank. The original PageRank source is [Page et al., “The PageRank Citation Ranking: Bringing Order to the Web” (1998)](https://ilpubs.stanford.edu/422/); it is a Stanford technical report with no DOI. |
| `fused` | RRF of hybrid retrieval and the PPR article ranking. | The fusion is [Cormack et al. (2009)](https://doi.org/10.1145/1571941.1572114); the graph ranker is [Haveliwala (2002)](https://doi.org/10.1145/511446.511513). This particular pairing is project-specific. |
| `mmr` | Greedy maximal-marginal-relevance reranking of PPR scores, using Jaccard similarity between article entity-neighbor sets as the redundancy penalty. | [Carbonell & Goldstein, “The Use of MMR, Diversity-Based Reranking for Reordering Documents and Producing Summaries” (1998)](https://doi.org/10.1145/290941.291025). The entity-set similarity and score parameterization here are project adaptations. |
| `graph_rwr` | Personalized/random-walk-with-restart PageRank over the candidate article/entity graph. | [Page et al. (1998)](https://ilpubs.stanford.edu/422/) and the query/topic-personalized extension [Haveliwala (2002)](https://doi.org/10.1145/511446.511513). |
| `graph_hits` | Query-seeded HITS; graph authorities provide article scores for entity seeds. | [Kleinberg, “Authoritative Sources in a Hyperlinked Environment” (1999)](https://doi.org/10.1145/324133.324140). |
| `graph_salsa` | SALSA-style alternating random walks between entity and article nodes, with seed restart in this implementation. | [Lempel & Moran, “SALSA: The Stochastic Approach for Link-Structure Analysis” (2001)](https://doi.org/10.1145/382979.383041). The fixed iteration count and restart behavior are implementation adaptations. |
| `graph_path` | Project-specific short-path evidence: direct seed-article matches plus discounted evidence through shared entities. | No standalone academic method paper was identified for this exact scoring rule. It is a custom heuristic rather than a direct implementation of a named published path-ranking algorithm. |
| `graph_walk` | Project-specific, bounded two-hop typed walk with degree normalization and hop decay. | No standalone paper was identified for this exact bounded scoring rule. [Lempel & Moran’s SALSA paper](https://doi.org/10.1145/382979.383041) is a related bipartite random-walk method, not the origin of this implementation. |
| `graph_fusion` | RRF of hybrid retrieval and query-seeded HITS graph ranking. | [Cormack et al. (2009)](https://doi.org/10.1145/1571941.1572114) for RRF; [Kleinberg (1999)](https://doi.org/10.1145/324133.324140) for HITS. The combination is project-specific. |
| `graph_hits_cross_encoder` | HITS on a query-entity/article bipartite graph whose edges are weighted by cross-encoder relevance probabilities. | [Kleinberg (1999)](https://doi.org/10.1145/324133.324140) for HITS and [Nogueira & Cho (2019)](https://doi.org/10.48550/arXiv.1901.04085) for neural passage reranking. The probability-weighted graph construction is project-specific. |
| `ensemble_rrf` | RRF across a configurable set of component rankings (default: `rrf`, `cross_encoder`, and `ppr`). | [Cormack et al. (2009)](https://doi.org/10.1145/1571941.1572114) introduced the fusion rule. The selected component ensemble is project configuration. |

## Graph seeding methods

| Implemented seed option | Method used in this project | Academic source / qualification |
|---|---|---|
| `louvain` | Project the article/entity graph onto entity nodes, find Louvain communities, then select the most connected entities from each surviving community. | [Blondel et al., “Fast Unfolding of Communities in Large Networks” (2008)](https://doi.org/10.1088/1742-5468/2008/10/P10008) introduced the Louvain community-detection method. The projection, community-size filtering, and per-community top-entity pooling are project-specific seeding steps. |
| `hits` | Select top entity nodes by HITS authority score (computed from article-to-entity links) as PPR personalization seeds. | [Kleinberg (1999)](https://doi.org/10.1145/324133.324140) introduced the hubs-and-authorities method. Choosing the top fraction as seeds is project-specific. |
| `ppr_top10` | Select the top 10% of entity nodes by unpersonalized PageRank divided by the square root of opposite-node degree; use them as PPR seeds. | PageRank source: [Page et al. (1998)](https://ilpubs.stanford.edu/422/) (no DOI). The top-10% cutoff and degree normalization are project-specific; no separate originating paper was identified for that heuristic. |
| `query_entities` | Extract person/organization/location mentions from the query, match them to graph entities (preferring canonical DBpedia identities), and seed those nodes. | The query-to-graph seeding rule is project-specific. For its DBpedia entity-linking component, see [Mendes et al., “DBpedia Spotlight: Shedding Light on the Web of Documents” (2011)](https://doi.org/10.1145/2063518.2063519). The citation concerns entity linking, not this seeding strategy. |

## References and interpretation notes

- The implementation exposes variants and combinations, not all-new academic algorithms. The citations above point to the underlying method papers; custom adaptations are explicitly labeled.
- In particular, the current lexical SQL uses PostgreSQL `ts_rank` (named `bm25` in the query) rather than the standard BM25 formula. `hybrid_max` also currently returns the hybrid RRF retrieval ranking; it is not a max-score fusion implementation.
- DOI links are provided where available. The original PageRank technical report has no DOI, so its Stanford-hosted copy is linked directly.
